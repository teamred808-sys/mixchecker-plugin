# Code signing policy

Code signing is not active for this project at this time. No binary should be described as SignPath Foundation-signed unless it has a valid signature from a release processed under an accepted SignPath Foundation project and this policy has been updated.

Before activation, the project must identify its authors, reviewers, and approvers by name, enable multi-factor authentication for all team members on GitHub and SignPath, and publish this policy on the project home page and download/release pages. Every release signing request will require manual approval. The official build will run on GitHub-hosted runners from this public source repository; signed artifacts will be linked to the corresponding source revision and release.

The project's privacy and network behavior is documented in [PRIVACY.md](PRIVACY.md). Before applying, maintainers must confirm the project and all included components use OSI-approved licenses and are not offered under a commercial dual-licensing model, as required by the Foundation's eligibility terms.

Required provider statement for an accepted and configured project: “Free code signing provided by SignPath.io, certificate by SignPath Foundation.” This statement is included as a planned policy only; signing is not active and Foundation approval has not been granted.
